# CLAUDE.md — инструкция для Claude Code

Проект: self-hosted платформа мониторинга станков с ЧПУ (Fanuc 0i-MD и др.) и расчёта OEE.
**Полное описание архитектуры — `ARCHITECTURE.md`. Прочитай его целиком перед любой работой.**

## Как работаем

- Работаем строго по этапам из `ARCHITECTURE.md`, раздел 11. Не забегай вперёд: не делай функционал следующих этапов, пока текущий не соответствует критерию готовности.
- В начале этапа — короткий план (файлы, шаги), затем реализация, затем проверка критерия готовности (запуск, тесты) и краткий отчёт.
- Если решение расходится с `ARCHITECTURE.md` — не меняй молча: предложи изменение, после согласования обнови `ARCHITECTURE.md` и добавь ADR в `docs/adr/NNNN-название.md`.
- Язык: код, идентификаторы, комментарии в коде, коммиты — на английском. Документация в `docs/` и общение — на русском. Тексты UI — на русском (через i18n-словарь, не хардкодом).
- В конце каждой задачи обновлять `docs/PROJECT_STATE.md` — сводку для продолжения работы в новом чате: состояние кода (PR, что сделано), открытые вопросы, следующий шаг. Без адресов заводской сети, паролей и токенов: репозиторий публичный.

## Нерушимые правила архитектуры

1. **Сырые данные (`telemetry`, `machine_events`) только INSERT.** Никаких UPDATE/DELETE, кроме политик retention.
2. **Всё производное пересчитываемо.** `state_intervals`, `part_events`, `oee_*` должны полностью восстанавливаться из сырых данных + справочников функцией пересчёта за период. Любая новая производная сущность обязана поддерживать пересчёт.
3. **Edge без бизнес-логики.** Коллектор только читает, ставит `ts` (UTC), буферизует, отправляет. Определение состояний, OEE, нормы — только на сервере.
4. **Время.** Везде UTC, `timestamptz`. `ts` — время чтения на edge; `received_at` — время приёма. Локальное время только при отображении и в границах смен (часовой пояс площадки в конфиге).
5. **Идемпотентность.** Приём сообщений по `msg_id` (`ON CONFLICT DO NOTHING`). Повторная доставка не должна ничего менять.
6. **Контракт сообщений** — только через `shared/schemas/*.json`. Изменение формата = новая версия схемы (`telemetry.v2`), старая поддерживается до миграции всех коллекторов.
7. **Аннотации пользователей привязаны ко времени**, не к id интервалов.
8. **Миграции БД только через Alembic.** Никаких ручных DDL.
9. **Модули backend изолированы:** `ingest`, `timeline`, `oee`, `reports`, `geometry`, `repairs`, `api`, `admin` (и будущий `notify`) общаются через сервисные функции/интерфейсы, а не лезут в таблицы друг друга напрямую. Общее — только в `core`.
10. **Библиотеки FOCAS (Fwlib*.dll, libfwlib32.so) не коммитить** — только `edge/vendor/` в `.gitignore`.
11. Секреты — только через переменные окружения / `.env` (в git — `.env.example`).

## Стек и инструменты

- Python 3.12, менеджер `uv`. Backend: FastAPI, SQLAlchemy 2 async, asyncpg, Alembic, pydantic v2, aiomqtt, redis-py.
- Edge: Python 3.12, ctypes, paho-mqtt, SQLite, pydantic; образ Docker (Linux). Сборка `.exe` для Windows (PyInstaller) пока не сделана.
- Frontend: React 18 + TypeScript + Vite, pnpm, TanStack Query, react-router-dom, Tailwind, ECharts. API-клиент пока написан вручную (`frontend/src/api/client.ts`): генерация из OpenAPI — когда у маршрутов появятся модели ответов.
- БД: PostgreSQL 16 + TimescaleDB. Кэш/live: Redis 7. Брокер: Mosquitto 2.
- Качество: `ruff` (lint+format), `mypy --strict` для `backend/app` и `edge/collector`, `pytest`, `testcontainers` для интеграционных тестов; фронтенд — проверка типов `tsc` и сборка. Модульных и e2e-тестов фронтенда, линтера JS и pre-commit пока нет — не ссылаться на них, пока не добавлены.
- CI — GitHub Actions (`.github/workflows/ci.yml`): backend (ruff, mypy, pytest), edge (ruff, mypy, pytest), frontend (сборка), deploy (compose-файлы, Caddyfile, shellcheck), сборка Docker-образов. Pull request сливается в `main` только с зелёными проверками.


## Тестирование

- **Симулятор — основной инструмент проверки.** `edge/collector/drivers/simulator.py` поддерживает сценарии (YAML в `edge/scenarios/`): нормальная работа, частые простои, авария, обрыв связи, сброс счётчика деталей, смена программы. Опоздавшие данные из буфера проверяются тестами буфера edge и сквозными тестами backend (перезапуск коллектора с непустым буфером).
- Для таймлайна и OEE — **golden-тесты**: сценарий → ожидаемые интервалы и метрики (`backend/tests/golden/`). Любое изменение правил/формул должно проходить golden-тесты или явно обновлять эталоны с объяснением.
- Интеграционные тесты на реальном PostgreSQL+TimescaleDB через testcontainers, без моков БД.
- Перед завершением этапа: `make lint && make test` зелёные, `make up` поднимается с нуля на чистых томах, CI на pull request зелёный.

## Edge-коллектор: важные детали

- Работа на Windows (служба) и Linux (Docker/systemd). Пути и библиотека FOCAS — из конфига.
- FOCAS-вызовы не потокобезопасны на одном хендле: один хендл — один поток (станок).
- Любой вызов FOCAS возвращает код ошибки (`EW_*`) — обрабатывать каждый, логировать с кодом, при сетевых ошибках переподключаться с backoff 1→30 с.
- Если функция не поддерживается стойкой (`EW_FUNC`, `EW_NOOPT`) — отключать этот сигнал для станка, а не падать.
- Счётчик деталей: источник настраивается (`macro #3901` / `param 6711`). Сброс счётчика (значение уменьшилось) — не отрицательный выпуск; обрабатывается на сервере в `part_events`.
- Сначала запись в SQLite-буфер, потом публикация; удаление из буфера только после PUBACK.

## Frontend: UX-требования

- Экран оператора — для планшета в цеху: крупные элементы (кнопки ≥ 64 px), высокий контраст, работа в перчатках, без мелкого текста, без hover-зависимого UI. Ввод причины простоя — максимум 2 касания.
- Цеховой дашборд — для ТВ 1080p/4K, читаемость с 5 м, без взаимодействия, автообновление по WebSocket, автоматическое переподключение.
- Единые цвета состояний: RUN #22c55e, IDLE #eab308, STOP #ef4444, ALARM #a855f7, SETUP #3b82f6, OFFLINE #6b7280.
