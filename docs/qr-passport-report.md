# Отчёт: QR-паспорт станка (feat/qr-passport)

Дата: 2026-11-25 · Ветка: `feat/qr-passport` · Решение: ADR 0009

## Итог

У каждого станка — постоянный случайный код из 8 знаков. Наклейка ведёт на `https://<host>/m/<код>`, в QR только
ссылка. Без входа открывается форма входа, после неё — снова страница станка. Дальше по роли: мастер, технолог,
администратор — состояние, показатели смены, таймлайн и заявка на ремонт; сервис — карточка станка; оператор —
экран оператора. Неверный код, станок другой организации и станок вне узлов роли — одинаковое «нет доступа».
Администратор печатает наклейку станка (PDF 90 × 50 мм) и лист наклеек участка (A4, 10 штук) и перевыпускает код:
старая наклейка сразу перестаёт работать. Страницы проверены в браузере на ширине телефона 390 px.

## Что сделано

| Часть | Содержание |
|---|---|
| Код станка | Миграция `0011`: функция `new_passport_code()` (8 знаков из `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`, без 0/O и 1/I; случайность из `gen_random_uuid()`), `machines.passport_code` — NOT NULL, UNIQUE, значение по умолчанию. Код получили все станки при миграции и получает каждый новый, в том числе созданный `ingest` по входящим данным |
| API | `GET /passport/{code}` → `{machine_id, view}`: `service` / `machine` / `operator` по правам на станке, иначе 404; `POST /admin/machines/{id}/passport` — новый код; `GET /admin/machines/{id}/passport.pdf` — наклейка; `GET /admin/areas/{id}/passports.pdf` — лист участка. Все четыре — в тесте изоляции |
| PDF | `app/admin/stickers.py` (reportlab): QR (уровень M) со ссылкой и активной ссылкой в PDF, название станка, площадка · участок, код крупно, ссылка мелко; лист A4 2 × 5 с линиями реза, только активные станки. Шрифт — подмножество DejaVu Sans в `app/admin/fonts` с лицензией |
| Адрес на наклейке | `MM_PUBLIC_URL`, если задан; иначе адрес, по которому открыт интерфейс: nginx передаёт `X-Forwarded-Host` с портом и `X-Forwarded-Proto` (внешнего прокси, если он есть). `MM_PUBLIC_URL` — в `.env.example` и compose |
| Страница `/m/<код>` | Для телефона, одна колонка: состояние с таймером, причина, программа, последние данные; годные / план, OEE и брак смены, последний цикл и норма; таймлайн — смена (оставшееся время заштриховано), 12 ч, 24 ч, отрезок по касанию с причиной простоя, итоги по состояниям; открытые заявки станка, новая заявка (описание и необязательное время отказа), заявка по активной аварии одной кнопкой. Новых маршрутов чтения нет — страница берёт `/machines/{id}`, `/timeline`, `/repair-requests`, `/alarms` |
| Админка | «Станки»: колонка «QR-код», кнопки «Наклейка» и «Новый код» (с подтверждением); «Участки»: «Наклейки участка» |
| Вход | `next` принимает только путь этого сайта; поля логина без автозамены и заглавной буквы на телефоне |
| Телефон | Экран оператора: шрифты меньше на ширине до 640 px (планшет не изменился), ряд ввода брака переносится; карточка сервиса: таблица тестов прокручивается внутри карточки, ряды ввода переносятся |

## Найдено по ходу

| Что | Как нашлось | Что сделано |
|---|---|---|
| Переменная PL/pgSQL `code` совпала со столбцом `machines.code` — миграция падала на настоящей БД («column reference is ambiguous») | первый прогон тестов | переменная переименована, столбец указан с алиасом таблицы |
| nginx передавал API `Host` без порта — на наклейке была бы ссылка без `:8080` | разбор цепочки web → api | `X-Forwarded-Host $http_host` и `X-Forwarded-Proto` |
| После входа `next` мог увести на другой сайт (открытое перенаправление) | QR-вход полагается на `next` | принимается только путь этого сайта |
| Chromium сохраняет blob с кириллическим именем как «download» без расширения | браузерная проверка | имена файлов латиницей: `passport-<код станка>.pdf`, `passports-area-<id>.pdf` |
| Карточка сервиса на телефоне шире экрана на 6 px, таблица тестов сжата | браузерная проверка, ширины элементов | ряд ввода переносится, таблица прокручивается внутри карточки |
| Экран оператора на телефоне: значения и кнопки вылезают за плитки | снимок экрана | на ширине до 640 px шрифты меньше, кнопки по-прежнему не ниже 72 px |

## Решения, которые стоит подтвердить

- **Оператор** по наклейке попадает на экран оператора своего станка — в задаче оператор не назван. Права у него
  те же, что на планшете. Если операторам наклейка не нужна — одна строка в `open_passport`, ответ станет «нет доступа».
- **Суперадмин** попадает в карточку сервиса: у него есть право архива геометрии.
- **Кто перевыпускает и печатает**: администратор с ролью на площадке или организации (`structure.edit` на площадке
  станка) — как и правку станков в админке. Администратор с ролью только на участке — нет.
- **Лист участка** — только активные станки; наклейку выключенного станка можно скачать отдельно.
- **Состояние** на странице `/m/<код>` обновляется запросом раз в 10 с, а не по WebSocket: на телефоне в цеху так
  надёжнее, и не приходят состояния всех станков области доступа.
- **Карточка станка сервиса** — существующая (архив геометрии, отметки «столкновение», ремонты). Заявки и ТО станка
  у сервиса — в разделе «Ремонт и ТО»; показывать их в карточке — отдельной задачей, если нужно.
- **Продакшен за HTTPS-прокси**: задать `MM_PUBLIC_URL`, иначе на наклейке будет `http://`-адрес.
