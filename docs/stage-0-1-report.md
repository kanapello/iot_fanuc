## Этап 0 — проба FOCAS

Файл: `edge/tools/focas_probe.py`. Один самодостаточный файл: копируется на цеховой ПК
вместе с библиотекой Fanuc, других зависимостей кроме Python нет.

```bash
python edge/tools/focas_probe.py --ip <ip> --port 8193 --lib edge/vendor/Fwlib64.dll --watch
```

Что читает:

| Сигнал | Функция FOCAS |
|---|---|
| Статус с расшифровкой (режим, выполнение, движение, авария, аварийный останов) | `cnc_statinfo` |
| Номер программы (выполняемая / основная) | `cnc_rdprgnum` |
| Имя программы | `cnc_exeprgname` |
| Фактическая подача, обороты шпинделя | `cnc_actf`, `cnc_acts` |
| Нагрузка шпинделя | `cnc_rdspmeter` |
| Счётчик деталей: макро #3901 и параметр 6711 | `cnc_rdmacro`, `cnc_rdparam` |
| Активные аварии | `cnc_rdalmmsg2` |

Поведение:

- на каждый код `EW_*` (от −17 до 17) — отдельное сообщение на русском с подсказкой, что проверить;
- неподдерживаемый сигнал (`EW_FUNC`, `EW_NOOPT`) помечается и не прерывает пробу;
- потеря связи (`EW_SOCKET`, `EW_PROTOCOL`, `EW_HANDLE`) завершает пробу с кодом 1;
- отсутствие библиотеки или несовпадение разрядности — код 2 и объяснение.

**Что не проверено.** Раскладка структур под Windows и настоящую `Fwlib64.dll`. Тест
(`edge/tests/test_focas_probe.py`) компилирует поддельную библиотеку из
`edge/tests/fake_fwlib.c` и проверяет логику пробы, но не совпадение с DLL Fanuc.
Первый запуск на стойке — за владельцем проекта; если какое-то значение окажется
мусорным, это место надо править в первую очередь.

## Отступления от архитектуры — требуют подтверждения

По правилам проекта изменения согласуются заранее. Эти два внесены сразу, потому что без
них этап не собирался; оформлены как ADR со статусом «требует подтверждения».

1. **Ключ идемпотентности `(msg_id, ts)` вместо `msg_id`** — `docs/adr/0001-telemetry-idempotency-key.md`.
   TimescaleDB не позволяет уникальный индекс без колонки секционирования.
   `ARCHITECTURE.md`, п. 5.2 и 5.3, обновлён. Следствие для этапа 2: буфер edge должен
   хранить готовый конверт, а не пересобирать его при повторной отправке.
2. **PUBACK брокеру только после `COMMIT`, постоянная MQTT-сессия у `ingest`** —
   `docs/adr/0002-ingest-ack-after-commit.md`. Без этого падение `ingest` теряло бы
   сообщения. Цена: обращение к приватному атрибуту `aiomqtt` (публичного API ручного
   подтверждения там нет), версия библиотеки ограничена `<3`.

## Что отложено

| Что | Когда | Почему |
|---|---|---|
| Драйвер FOCAS в коллекторе, SQLite-буфер, heartbeat коллектора | этап 2 | по плану этапов |
| Постоянный `seq` | этап 2 | сейчас в памяти, после перезапуска коллектора начинается с 1 |
| Сценарий «опоздавшие данные из буфера» | этап 2 | без буфера его нечем воспроизвести |
| `redis`, `api`, `web` в compose | этапы 3–4 | пока нет кода, который их использует |
| Цели `gen-client`, `recalc`, `edge-build-win` в `Makefile` | вместе с соответствующим кодом | — |
| Остальные справочники (смены, причины, нормы, правила состояний) | этапы 3–5 | — |
| TLS на брокере, учётные записи на каждый коллектор | этап 6 | пока порт 1883 доступен только внутри сети compose |
| Prometheus-метрики приёма | этап 6 | сейчас счётчики раз в 30 с пишутся в лог `ingest` |

## Открытые вопросы к этапу 3

- **Порядок сообщений при нескольких экземплярах `ingest`.** Shared subscription не
  гарантирует порядок по станку, а state machine он нужен. До решения запускается один экземпляр.
- **FOCAS на Linux.** `libfwlib32.so` 32-битная: на x86_64 потребуется 32-битный Python
  или образ `i386`. Решать на этапе 2 при сборке `edge/Dockerfile` под реальный драйвер.
