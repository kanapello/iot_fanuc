# Установка на облачную VM

Сервер в интернете для внешних клиентов: HTTPS по домену, MQTT по TLS для коллекторов, ночные бэкапы в S3.
Устройство и решения — ADR 0010. Все команды выполняются в каталоге репозитория на VM.

## 1. Что нужно

| Что | Требование |
|---|---|
| VM | 4 vCPU, 8–16 ГБ RAM, SSD 200 ГБ; Ubuntu 24.04 LTS |
| Провайдер | с дата-центром в РФ (152-ФЗ: на сервере ФИО и логины пользователей, это персональные данные граждан РФ). Например, Yandex Cloud, VK Cloud, Selectel, Cloud.ru, Timeweb Cloud |
| Хранилище бэкапов | S3-совместимое хранилище того же провайдера (Yandex Object Storage, VK Cloud Storage, Selectel S3 и т. п.): закрытый бакет и ключ доступа только к нему (чтение, запись, список, удаление) |
| Сеть | публичный IPv4. Входящие: TCP 80, 443, 8883; SSH 22 — только с адресов администраторов. Остальное закрыто (группа безопасности провайдера и/или `ufw`) |
| DNS | A-запись домена (например, `mm.example.com`) на IP VM — **до** первого запуска |
| ПО | Docker Engine с плагином Compose 2.24 или новее, `git`, `make` |
| Почта | адрес для писем Let's Encrypt о сертификате |

Проверить DNS с любой машины:

```bash
dig +short mm.example.com
```

## 2. Установка

1. Docker (официальный способ для Ubuntu — документация Docker, пакеты `docker-ce` и `docker-compose-plugin`).
   Проверить версию Compose:

   ```bash
   docker compose version
   ```

2. Код и `.env` со случайными паролями:

   ```bash
   git clone https://github.com/kanapello/iot_fanuc.git /opt/machine-monitor
   ```

   ```bash
   cd /opt/machine-monitor
   ```

   ```bash
   make env-prod domain=mm.example.com email=ops@example.com
   ```

   Команда печатает пароль суперадмина — сразу сохраните его в менеджер паролей. Существующий `.env` она не
   перезаписывает.

3. Бэкапы — заполнить в `.env` (пример для Yandex Object Storage):

   ```
   MM_BACKUP_S3_ENDPOINT=https://storage.yandexcloud.net
   MM_BACKUP_S3_REGION=ru-central1
   MM_BACKUP_S3_BUCKET=mm-backups
   MM_BACKUP_S3_ACCESS_KEY=...
   MM_BACKUP_S3_SECRET_KEY=...
   ```

   Время ночного бэкапа — `MM_BACKUP_TIME` в UTC (23:30 UTC — 02:30 по Москве), хранение — `MM_BACKUP_KEEP_DAYS` (30).

4. Сохранить копию `.env` вне сервера (менеджер паролей, сейф). Без неё восстановление на новом сервере тоже
   возможно, но все пользователи войдут заново.

5. Запуск:

   ```bash
   make prod-up
   ```

   ```bash
   make prod-ps
   ```

   Все сервисы `Up`, `api`, `db`, `ingest`, `mosquitto`, `redis` — `healthy`. В логах Caddy — получение сертификата,
   в логах Mosquitto — строка `MQTT over TLS on 8883 with the certificate of mm.example.com`:

   ```bash
   make prod-logs s=caddy
   ```

   ```bash
   make prod-logs s=mosquitto
   ```

   Если Mosquitto пишет `waiting for the certificate`, Caddy ещё не получил сертификат: проверьте DNS и что порты
   80 и 443 открыты снаружи.

6. Открыть `https://mm.example.com`, войти суперадмином (`admin` и пароль из шага 2).

7. Убрать «Демо-предприятие», которое создают миграции (команда откажет, если у него есть данные):

   ```bash
   make prod-drop-demo
   ```

8. Бэкап и проверка восстановления — сразу после установки:

   ```bash
   make backup-now
   ```

   ```bash
   make restore-check
   ```

   В конце вывода — `restore check passed`. Проверке нужно свободное место на диске примерно с размер базы.

Если сервер не стартует и пишет `Refusing to start in production`, в `.env` остались значения из `.env.example` —
сообщение называет переменные. Пересоздайте `.env` командой `make env-prod` (старый переименуйте).

## 3. Подключение коллектора клиента

1. В админке суперадмином: организация клиента (код латиницей, например `acme`), затем администратором —
   площадка (код, часовой пояс) и коллектор (ID, например `edge-acme-1`) на этой площадке. Смены, причины простоя и
   нормы цикла организации — до первых данных, иначе план и OEE будут пустыми.
2. Учётная запись коллектора в брокере — дописать в `.env` (пароль — 32 случайных буквы и цифры, без `,` и `:`):

   ```
   MM_MQTT_COLLECTORS=edge-acme-1:acme:plant1:<пароль>
   ```

   Несколько коллекторов — через запятую. Применить (Mosquitto пересоздаётся, коллекторы переподключаются):

   ```bash
   make prod-up
   ```

3. Конфиг коллектора на площадке клиента (`edge/config.example.yaml`):

   ```yaml
   org: acme
   site: plant1
   collector_id: edge-acme-1
   mqtt:
     host: mm.example.com     # TLS и порт 8883 — по умолчанию, сертификат проверяется по системным корневым
     username: edge-acme-1
     password_env: MM_MQTT_PASSWORD
   ```

   Пароль — в переменной окружения `MM_MQTT_PASSWORD` службы коллектора.
4. Сеть клиента: исходящий TCP 8883 от ПК коллектора до сервера (`docs/runbooks/collector-network.md`); входящих
   соединений к клиенту не нужно.
5. Проверка: в логе коллектора — `MQTT connected to mm.example.com:8883`; в админке → «Коллекторы» — heartbeat;
   станки появляются сами при первых данных, им остаётся дать названия и участки.

## 4. Уведомления в Telegram

1. В Telegram у `@BotFather`: `/newbot`, имя и адрес бота (например, `mm_acme_bot`). BotFather выдаст токен.
2. В `.env`:

   ```
   MM_TELEGRAM_BOT_TOKEN=<токен от BotFather>
   MM_TELEGRAM_BOT_USERNAME=mm_acme_bot
   ```

   Применить:

   ```bash
   make prod-up
   ```

   В логе `worker` — `telegram notifications on`:

   ```bash
   make prod-logs s=worker
   ```

3. Серверу нужен исходящий доступ к `api.telegram.org:443`; входящих соединений и публичного адреса для бота не
   нужно (long polling). На установку — один `worker`: второй процесс с тем же токеном Telegram не пустит.
4. Каждый пользователь: «Профиль» (имя в правом верхнем углу) → «Подключить Telegram» → «Открыть Telegram» →
   «Запустить» в чате с ботом. Ссылка одноразовая и живёт 15 минут. Там же — какие события присылать.
5. Порог «простой без причины» — у участка в «Админка → Участки» (по умолчанию 10 мин). Одно и то же событие станка
   приходит не чаще раза в `MM_NOTIFY_REPEAT_MINUTES` (15) минут.

Кто что получает (ADR 0011): авария — мастер участка и сервис; батарея и вентилятор стойки — сервис; коллектор
не на связи дольше 5 мин и потерянный буфер — сервис и администратор организации; простой без причины — мастер
участка; новая заявка — сервис; смена статуса заявки — администратор и мастер; подходит ТО — сервис.

## 5. Обновление

```bash
make backup-now
```

```bash
git pull
```

```bash
make prod-up
```

`migrate` применяет миграции до старта `api`, `ingest` и `worker`. Проверить `make prod-ps` и логи.

## 6. Восстановление из бэкапа

Список копий:

```bash
make backup-list
```

**На том же сервере** (база заменяется копией целиком):

```bash
make restore file=latest confirm=yes
```

Вместо `latest` — имя файла из списка. Команда останавливает Caddy, `api`, `ingest`, `worker`, пересоздаёт базу,
восстанавливает её и запускает всё снова. Данные, пришедшие после копии, теряются; коллекторы досылают из своего
буфера то, что не успели отправить (до 7 дней).

**На новом сервере** (старый потерян): раздел 1 и шаги 1–4 раздела 2 с тем же `.env` (копия из шага 4; A-запись
домена перенести на новый IP), затем:

```bash
make restore file=latest confirm=yes
```

Команда поднимает пустую базу, восстанавливает в неё копию и запускает весь стек. С новым `.env` восстановление тоже
работает: пароли пользователей и ссылки киосков сохраняются, текущие сессии сбрасываются (все входят заново).

**На чистом томе** (база повреждена): остановить стек, удалить том БД и восстановить — так же:

```bash
make prod-down
```

```bash
docker volume rm machine-monitor_db-data
```

```bash
make restore file=latest confirm=yes
```

Раз в месяц — `make restore-check`: копия восстанавливается во временную чистую базу и сравнивается с рабочей.

## 7. Чек-лист перед первым клиентом

- [ ] DNS указывает на сервер, `https://<домен>` открывается с замком, `http://` переадресует на `https://`.
- [ ] Снаружи открыты только 80, 443, 8883 (и SSH с адресов администраторов). Проверка с другой машины:
      `nc -zv <домен> 1883` и `nc -zv <домен> 5432` — отказ; `openssl s_client -connect <домен>:8883 -servername <домен>`
      показывает сертификат Let's Encrypt для домена.
- [ ] Сервер стартует в prod (`make prod-ps` — всё `healthy`): значит, в `.env` нет паролей по умолчанию.
- [ ] Пароль суперадмина и копия `.env` — в менеджере паролей.
- [ ] «Демо-предприятие» удалено (`make prod-drop-demo`).
- [ ] `make backup-now` загружает копию, `make restore-check` заканчивается `restore check passed`; ночной бэкап
      появился в бакете на следующее утро.
- [ ] У сервисного инженера и суперадмина подключён Telegram: ошибку ночного бэкапа или `restore-check` и отсутствие
      успешного бэкапа дольше 26 часов они узнают из уведомления (тип «backup» в профиле).
- [ ] Организация, площадки, пользователи клиента созданы; смены, причины простоя и нормы цикла заведены.
- [ ] Коллектор клиента подключён по TLS, данные идут, станки названы и разнесены по участкам.
- [ ] QR-наклейки печатаются с адресом `https://<домен>/m/...` (адрес берётся из домена).
- [ ] Бот Telegram настроен, мастер и сервис подключили Telegram в профиле; пробное событие (например, заявка на
      ремонт) пришло в чат.
- [ ] Время на VM синхронизируется (NTP включён по умолчанию в Ubuntu).
