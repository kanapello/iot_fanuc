# Сеть коллектора: связь со стойками Fanuc

Для наладчика, который ставит коллектор на площадке. Коллектор сам открывает TCP-соединение FOCAS2
к каждой стойке (порт 8193) и сам отправляет данные на сервер (MQTT). Входящих соединений к коллектору нет.

## 1. Где стоит коллектор

Один из двух вариантов:

- **Коллектор в сети станков** — в том же сегменте (VLAN), что и Ethernet-порты стоек. Самый надёжный вариант:
  стойки доступны напрямую, без маршрутизаторов и межсетевых экранов.
- **Коллектор в другой подсети** — тогда из его подсети до каждой стойки должен быть открыт **TCP 8193**:
  на маршрутизаторе и межсетевом экране между сетями разрешены соединения с IP коллектора на IP стоек,
  порт 8193. Соединение открывает коллектор, обратных правил не нужно.

Со стороны стойки: включён встроенный Ethernet и FOCAS2, задан IP-адрес, маска (и шлюз, если коллектор
в другой подсети), TCP-порт FOCAS — 8193. Число одновременных подключений FOCAS у стойки ограничено:
другие программы, которые держат соединение со стойкой (системы мониторинга, утилиты ПК), могут не
оставить места коллектору.

Со стороны сервера: коллектору нужен исходящий доступ к брокеру MQTT сервера (адрес и порт — в
`config.yaml`, раздел `mqtt`).

## 2. На ПК коллектора не должно быть VPN и туннельных программ

VPN-клиенты (OpenVPN, WireGuard, Cisco AnyConnect, FortiClient и т. п.) и туннельные программы
(ZeroTier, Hamachi, Tailscale, Radmin VPN и т. п.) добавляют свои сетевые адаптеры и маршруты. Сеть
станков часто адресуется так же, как сети за VPN (`192.168.x.x`, `10.x.x.x`), и трафик к стойке уходит в
туннель вместо кабеля к станкам. Снаружи это выглядит как «стойка не отвечает» или как связь, которая
то есть, то нет.

На ПК коллектора такие программы удаляют (а не только отключают: многие поднимаются сами после
перезагрузки). Удалённый доступ к ПК коллектора — средствами, которые не меняют его маршруты.

Посмотреть адаптеры, включая виртуальные (TAP, Wintun, ZeroTier и подобные):

```powershell
Get-NetAdapter | Format-Table Name, InterfaceDescription, Status
```

## 3. Проверка пути: Find-NetRoute

Какой адаптер и какой маршрут Windows выберет для стойки (подставьте IP стойки):

```powershell
Find-NetRoute -RemoteIPAddress 192.168.10.57 | Format-List InterfaceAlias, IPAddress, DestinationPrefix, NextHop
```

Правильно:

- `InterfaceAlias` — адаптер, который смотрит в сеть станков (например, «Ethernet 2»);
- `IPAddress` — адрес ПК коллектора в этой сети;
- `NextHop` — `0.0.0.0`, если стойка в той же подсети, или адрес маршрутизатора сети станков.

Неправильно: в `InterfaceAlias` VPN- или туннельный адаптер, Wi-Fi вместо кабеля к станкам, или маршрут
по умолчанию (`DestinationPrefix 0.0.0.0/0`) там, где стойка должна быть в своей подсети. Тогда — раздел 2
или неверные IP-адрес и маска на ПК коллектора.

## 4. Порядок проверки

Сверху вниз; следующий шаг — только когда прошёл предыдущий.

### 4.1. ping

```powershell
ping 192.168.10.57
```

Нет ответа — проблема ниже TCP: кабель и порт коммутатора, IP-адрес и маска на ПК и на стойке, VLAN,
питание ЧПУ, включён ли встроенный Ethernet. Сначала `Find-NetRoute` (раздел 3).

### 4.2. Test-NetConnection

```powershell
Test-NetConnection 192.168.10.57 -Port 8193
```

Нужно `TcpTestSucceeded : True`. Если ping проходит, а порт закрыт: на стойке не включён FOCAS2 или
задан другой порт, порт 8193 закрыт межсетевым экраном между подсетями, все подключения FOCAS стойки
заняты другими программами.

### 4.3. Проба FOCAS

```powershell
python focas_probe.py --ip 192.168.10.57 --port 8193 --lib C:\collector\vendor\Fwlib64.dll --out probe.txt
```

Проба печатает модель ЧПУ, серию и версию ПО, число осей, статус, программу, подачу, обороты, нагрузку,
счётчик деталей и аварии, у каждого вызова — время ответа. `--out` дописывает весь вывод в файл UTF-8 —
его и пересылают разработчикам.

| Результат пробы | Что это значит | Что делать |
|---|---|---|
| Код выхода 2, «Библиотека FOCAS не найдена» или «Не удалось загрузить» | нет файла или разрядность Python не совпадает с библиотекой | `Fwlib64.dll` — 64-битный Python, `Fwlib32.dll` — 32-битный |
| `EW_NODLL (-15)` | библиотека не нашла вспомогательные DLL | `Fwlib64.dll`, `fwlibe64.dll`, `fwlib0iD64.dll` — в одной папке; проба сама ставит её первой в `PATH` |
| `EW_SOCKET (-16)` | нет TCP-соединения со стойкой | вернуться к 4.1–4.2 |
| `EW_PROTOCOL (-17)` | на порту отвечает не FOCAS | проверить порт и IP |
| `EW_FUNC (1)`, `EW_NOOPT (6)` у отдельных сигналов | сигнал не поддерживается стойкой | не ошибка связи: коллектор отключит этот сигнал для станка |
| Время ответа вызовов — сотни миллисекунд и больше | медленный или перегруженный путь | `Find-NetRoute`, нет ли VPN или Wi-Fi на пути |

## 5. Коллектор на Linux

То же самое другими командами:

```bash
ip route get 192.168.10.57
```

```bash
ping -c 3 192.168.10.57
```

```bash
nc -zv 192.168.10.57 8193
```

В контейнере коллектор выходит к стойкам через сеть хоста, поэтому маршрут к сети станков должен быть
у самого хоста.
