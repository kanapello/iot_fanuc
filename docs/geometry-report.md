# Отчёт: геометрическая точность — архив сервиса

Дата: 2026-11-22 · Ветка: `feat/geometry-archive` · Решение — ADR 0005 (пересмотрен)

## Итог

Модуль геометрии упрощён до внутреннего архива сервиса с трендом. Его видят только сервис и суперадмин;
для пользователей клиента архива нет — все его маршруты отвечают 404, даже по своим станкам. Анализ
(допуски, статусы, сроки проверок) и разбор `.b5r` убраны и отложены.

## Что осталось

| Что | Как |
|---|---|
| Тесты в карточке станка | Настройка теста и ручной ввод результатов по каталогу параметров с единицами; ошибочный тест аннулируется, не удаляется |
| Оригиналы `.b5r` и PDF | В PostgreSQL, до 25 МБ; триггер запрещает изменение и удаление |
| Полярный график | Если у теста есть точки круга (API импорта `PUT /ballbar/tests/{id}/traces`) |
| Тренд параметра | Тесты одного шаблона (без учёта регистра и пробелов); без шаблона — одинаковые плоскость, радиус, подача и **дуга** |
| События на тренде | Отметки «столкновение» и выполненные ремонты — вертикальные линии на графике |
| Карточка станка | Дата последнего теста и сколько дней прошло, без статусов |
| Экран «Сервис» | Список станков архива: последний тест, дней прошло, число тестов — чтобы сервису было откуда открыть карточку |
| Отметка «столкновение» | Ставят оператор и мастер (экран оператора), а также сервис; видят только сервис и суперадмин |

## Что удалено

Допуски на станок и модель, поле `machines.model`, подсветка превышений, политики и расчёт следующей
проверки, внеплановые проверки по авариям, рабочий список сервиса, заготовка разбора `.b5r` и его
golden-тест. Вспомогательные функции, нужные только этим частям (наработка с даты, аварии с даты),
тоже удалены. Таблицы, индекс и поля удаляет миграция `0006`; миграции `0004`–`0005` не менялись.

## Добавлено

**Журнал выполненных ремонтов** (`repair_records`: дата, описание, инженер) в карточке станка — источник дат
ремонтов для тренда. Модуля ремонтов в системе нет, поэтому журнал минимальный и ведётся сервисом вручную.
Это решение стоит подтвердить: возможно, даты ремонтов должны приходить из будущего модуля заявок на ремонт.

## Проверка

| Проверка | Результат |
|---|---|
| `make lint` (ruff, `mypy --strict`, `tsc`) | чисто |
| Backend | 64 теста зелёные |
| Edge | 23 теста зелёные |
| Доступ | пользователи клиента (администратор, технолог, мастер, оператор, киоск, ТВ) получают 404 на всех 16 маршрутах архива по своему станку, данные не меняются; пункт меню скрыт; оператор, мастер и киоск ставят отметку «столкновение», технолог — нет (403) |
| Изоляция | чужая организация не видит ничего на всех закрытых маршрутах; данные организации A видит её администратор, а архив — сервис |
| Тренд | группировка по шаблону и по полной настройке с дугой, аннулированный тест не попадает; события между тестами есть, до первого теста — нет |
| Стенд | карточка станка под сервисом: последний тест и дни, тренд с отметками столкновения и ремонта, полярный график; мастер не видит пункта «Сервис», карточка ему недоступна; киоск ставит отметку «столкновение» |

## Ограничения

- Отметки «столкновение» и ремонты нельзя исправить или удалить — только добавить.
- Точки круга загружаются только через API, формы импорта в интерфейсе нет.
- Клиент не видит результатов геометрии в системе; отчёт ему передаётся вне системы.
