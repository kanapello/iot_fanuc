# Отчёт: геометрическая точность (Renishaw QC20, Ballbar 20)

Дата: 2026-11-17 · Ветка: `feat/geometry-ballbar` · Решения — ADR 0005

## Итог

В карточке станка ведутся тесты ballbar: настройка теста, результаты с единицами, оригиналы `.b5r` и
PDF-отчётов, сырые точки круга с полярным графиком, допуски, тренд и срок следующей проверки. Экран
сервиса собирает в один список превышения допусков и проверки, которые пора делать. Автоматического
разбора `.b5r` пока нет — подготовлены место для образцов и golden-тест.

## Что сделано по пунктам задачи

| Пункт | Как сделано |
|---|---|
| Тест в карточке станка: дата, инженер, плоскость XY/YZ/ZX, радиус, подача, дуга 360/220, температура, шаблон | Таблица `ballbar_tests`; карточка `/machines/:id`, форма ввода. Температура — воздуха и станка отдельно. Ошибочный тест аннулируется с причиной, не удаляется |
| Загрузка оригинала `.b5r` и PDF-отчёта, хранить всегда | `ballbar_files` в PostgreSQL, до 25 МБ; принимаются только `.b5r` и PDF (проверяется заголовок `%PDF-`). Триггер запрещает UPDATE и DELETE даже напрямую в БД. Исправленный отчёт загружается ещё одним файлом |
| Результаты — набор параметров с единицами: ISO 230-4 и диагностика Renishaw | Каталог `app/geometry/catalog.py`: круглость, круговое отклонение, круговой гистерезис (общие и по направлениям); неперпендикулярность (µm/m), люфт, реверсивный пик, боковой зазор, циклическая ошибка, ошибка масштаба (ppm), прямолинейность — по осям плоскости; рассогласование приводов (ms). Оси подставляются из плоскости, лишние ключи отклоняются |
| Ввод вручную формой | Форма в карточке станка по группам отчёта; пустые поля не сохраняются; запятая как разделитель принимается |
| Разбор `.b5r` — отдельной задачей, golden-тесты «файл → числа отчёта» | `backend/tests/fixtures/ballbar/README.md` — формат образцов (`.b5r` + PDF + `expected.json`); `tests/golden/test_b5r_parser.py` пропускается без образцов и упадёт с первым образцом, пока не написан `app/geometry/b5r.py` |
| Хранилище сразу под сырые точки круга (полярный график) | `ballbar_traces`: массивы углов и отклонений на направление прохода; API импорта `PUT /ballbar/tests/{id}/traces` (до 200 000 точек), прореживание для графика; полярный график в карточке |
| Допуски по параметру на станок или модель станка | Поле `machines.model`; допуски станка и модели с необязательными плоскостью и осью; выбирается самая узкая строка, станок важнее модели. Превышение — по модулю, подсветка строки в тесте |
| Превышение — пункт на экране сервиса | Экран `/service`: превышения в последнем тесте каждой плоскости, плюс проверки к выполнению; после нового теста без превышений пункт исчезает |
| Тренд только по тестам с одинаковыми плоскостью, радиусом и подачей | `GET /machines/{id}/ballbar/trend` и график с линией допуска; выбор набора «плоскость · радиус · подача» из имеющихся |
| Следующая проверка: по сроку, по наработке из мониторинга, по событию | Политика станка (по умолчанию 180 дней): срок от последнего теста, наработка — время RUN из таймлайна, события — авария по шаблонам (по умолчанию `SV`, `servo`, `overload`, `OVC`, `OVL`) или отметка «столкновение» после теста. Статусы: тестов не было, в норме, скоро (14 дней или 10 % наработки), просрочена, внеплановая |
| Отметка «столкновение» | Кнопка на экране оператора (подтверждение вторым касанием) и в карточке станка; таблица `collision_marks` |

## Проверка

| Проверка | Результат |
|---|---|
| `make lint` (ruff, `mypy --strict`, `tsc`) | чисто |
| Backend | 67 тестов зелёные, 1 пропущен (golden-тест `.b5r` ждёт образцы) |
| Edge | 23 теста зелёные |
| Правила (чистые функции) | ключи параметров по плоскости, выбор допуска, превышение по модулю, все статусы следующей проверки, шаблоны аварий |
| Тесты на БД через API | тест с результатами и проверкой ввода; загрузка и скачивание `.b5r` и PDF (кириллица в имени); неизменяемость оригиналов в БД; точки круга; аннулирование; тренд только по одинаковой настройке; допуск станка против допуска модели; наработка из таймлайна (1 ч RUN → 1,01 ч); авария SV0401 и «столкновение» после теста; рабочий список и его очистка новым тестом; права ролей |
| Изоляция | тест обходит все 49 закрытых маршрутов, в том числе 20 новых, от имени чужой организации: ни одного чужого имени, база не меняется |
| Браузер (стенд) | сервис видит 6 пунктов по двум площадкам; новый тест вводится формой, превышение подсвечивается; PDF загружается и скачивается; киоск отмечает столкновение; мастер видит тесты без кнопки ввода; ошибок на страницах нет |

Найдено по ходу: в установленной версии FastAPI вложенный роутер не раскрывается в общий список маршрутов —
тест изоляции молча пропустил бы новые маршруты. Роутеры приложения теперь перечислены явно
(`API_ROUTERS`), и тест обходит ровно этот список.

## Решения, которые стоит подтвердить (ADR 0005)

1. **Сервис впервые пишет данные клиентов** — тесты, файлы, допуски, правила проверки, отметки «столкновение» —
   по станкам всех организаций. В ADR 0004 сервис только читал.
2. **Допуски моделей общие для всех организаций** и ведутся сервисом; администратор организации задаёт только
   допуски своих станков (они важнее модели).
3. **Оригиналы в PostgreSQL**, до 25 МБ на файл (`MM_GEOMETRY_MAX_FILE_MB`); nginx пропускает до 30 МБ.
4. **Дуга не входит в ключ тренда** — как в задаче: плоскость, радиус, подача. Если 360° и 220° в одной
   плоскости сравнивать нельзя — добавить дугу в ключ (одна строка).
5. **Допуск не зависит от радиуса и подачи теста.** Если в паспорте модели допуск круглости задан для
   конкретного радиуса — добавить их в ключ допуска.
6. **Политика по умолчанию** — 180 дней, без наработки, аварии и столкновения включены.
7. **Отметить столкновение** могут оператор, мастер и все, кто ведёт геометрию (технолог, администратор, сервис).

## Ограничения

- **Разбора `.b5r` нет**; точки круга пока попадают только через API импорта (и в демо-данных — синтетические,
  с пометкой «демо-точки»).
- **Правки результатов не журналируются.** Тест можно исправить; оригиналы неизменны, но история ручных правок
  значений не хранится.
- **Наработка считается только по времени мониторинга.** Если последний тест был до подключения станка,
  часы до подключения не учитываются.
- **Рабочий список считается при каждом запросе** — для сотен станков достаточно; уведомления (Telegram, почта)
  по нему не отправляются.
- **Допуск на направление прохода** (отдельно по ч. с. и против) не задаётся — только на параметр, плоскость и ось.
- **Демо-данные** (`MM_DEMO_DATA=true`) — выдуманные значения и синтетические точки, инженер «Демо-данные».
