# Отчёт: сквозной каркас на симуляторе

Дата: 2026-11-17 · Ветка: `feat/skeleton`

## Итог

`make up` на чистых томах поднимает всю цепочку: симулятор (6 станков) → SQLite-буфер →
MQTT → `ingest` → сырые данные → `worker` (таймлайн, детали, OEE, live в Redis) → API →
веб-интерфейс. Через ~30 с после старта экраны заполнены историей за 8 часов.

Этап 0 (проба FOCAS) и новый драйвер FOCAS **на реальной стойке не проверены** — только на
поддельной библиотеке.

## Что упрощено

**Edge**
- Буфер вытесняет только по возрасту, без приоритета событий над телеметрией.
- После переподключения к брокеру буфер отправляется заново целиком; дубликаты гасит сервер.
- Драйвер FOCAS не читает overrides подачи и шпинделя.
- Досылка истории идёт с шагом 5 с, а не 1 с.

**Таймлайн**
- `make recalc` перестраивает таймлайн от `from` до текущего момента; `to` ограничивает только OEE.
- Режимы EDIT/MDI/JOG/HND сразу дают SETUP, без порога «дольше N минут».
- Интервал несёт программу, активную на его начало; смена программы внутри интервала его не делит.
- Открытая причина простоя закрывается worker'ом при следующем запуске станка, то есть worker меняет запись пользовательского ввода.
- Таймлайн достраивается для всех активных станков каждые 2 с, без уведомлений из БД.

**OEE**
- Календарь смен вычисляется из шаблонов на лету; таблицы `shift_calendar` нет, исключений (праздники, отдельные графики станков) нет.
- Норма цикла берётся последняя по программе; `valid_from` хранится, но не учитывается.
- План/факт на экранах считается по норме текущей программы за всю смену.
- Брак относится к смене по времени ввода.
- Изменение смен, норм или правил не запускает пересчёт само — нужна кнопка или `make recalc`.
- Парето считает простои за всё время периода, включая нерабочее и перерывы.

**API и интерфейс**
- Действия оператора не подписываются табельным номером или PIN.
- Нет экспорта CSV/XLSX, отчёта «выпуск план/факт», трендов.
- Дашборд без авторотации участков.
- Админка — простые таблицы; поля «дни недели» и «перерывы» редактируются как JSON.
- Периоды «Сегодня» и «Вчера» считаются по часовому поясу браузера, а не площадки.

## Что нужно укрепить дальше

1. **Проверить FOCAS на реальной стойке** — пробу и драйвер; сверить раскладку структур с `Fwlib64.dll`.
2. **Интеграционный тест edge с настоящим брокером.** Блокировку в публикаторе модульные тесты не поймали.
3. **Тесты на отказы edge**: обрыв сети на 10 минут, перезапуск коллектора с непустым буфером.
4. **Тесты API и worker на реальной БД** — сейчас покрыты только чистые функции и приём.
5. **Пересчёт за закрытый период** с корректной стыковкой на границе `to`.
6. **Порядок сообщений при нескольких экземплярах `ingest`**, проверка разрывов `seq` на сервере.
7. **Нагрузка**: 200 станков при 1 Гц, длинные пересчёты, инкрементальный OEE вместо пересчёта всего диапазона.
8. **Авторизация**: пользователи и роли в БД, токен киоска на станок, PIN оператора, срок жизни device-токена.
9. **Календарь смен**: материализованный, с исключениями и графиком на станок или участок.
10. **Нормы цикла с периодами действия** и автоматический пересчёт при изменении справочников.
11. **Уведомления** (простой без причины, авария, коллектор offline) — модуль `notify` не начат.
12. **Генерация TS-клиента из OpenAPI**, модели ответов в API, тесты и линтер фронтенда.
13. **Эксплуатация**: TLS, Prometheus, бэкапы, установщик Windows — сознательно не делались.

## Отступления от ARCHITECTURE.md и CLAUDE.md

| Документ требует | Сделано | Почему |
|---|---|---|
| Изменение формата — новая версия схемы | Поля добавлены прямо в `telemetry.v1` | так поставлена задача; развёрнутых коллекторов нет |
| `ingest` ведёт state machine и обновляет Redis | `ingest` только пишет и помечает период; таймлайн и Redis — в `worker` | так поставлена задача |
| Таблица `shift_calendar` | Смены считаются из `shift_templates` на лету | проще, нет второго источника правды |
| `users`, `roles`, RBAC из четырёх ролей | Один администратор из `.env` и общий device-токен | так поставлена задача |
| `user_id` в записях оператора | Текстовое поле `operator`, пока пустое | нет таблицы пользователей |
| Очередь задач `jobs` (`SKIP LOCKED`) | Таблица `timeline_dirty` и advisory-блокировка на станок | одной отметки «с какого момента» достаточно |
| `recalc(machine, from, to, scope)` | Таймлайн всегда до текущего момента, без `scope` | таймлайн — одна цепочка интервалов |
| TS-клиент генерируется из OpenAPI | Небольшой клиент написан вручную | в API пока нет моделей ответов |
| TanStack Router | `react-router-dom` | проще для четырёх маршрутов |
| `vitest`, `eslint`, `prettier` | Только проверка типов `tsc` | минимальные тесты — только ядро |
| Интеграционные тесты без моков БД | Golden-тесты на чистых функциях без БД | быстрее и точнее для правил и формул |
| Модули общаются только через сервисные функции | `reports` и `admin/journal` читают `state_intervals` своим SQL | один запрос вместо выгрузки интервалов в Python |
| Справочники по этапам, пользовательский ввод отдельно | Причины, брак и отметки наладки лежат в модуле `admin` | меньше модулей в каркасе |
| Redis-образ `redis:7`, сохранение у брокера и БД | `redis:7-alpine` без сохранения на диск | Redis — только кэш |
| Симулятор только читает «станок» в реальном времени | При первом старте досылает 8 ч истории с прошлыми метками времени | чтобы экраны не были пустыми сразу после `make up` |
| ADR на каждое отступление | ADR не писались | так поставлена задача |
