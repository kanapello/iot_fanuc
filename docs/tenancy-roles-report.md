## Итог

Система различает, чьи данные и кто их может видеть. Одна установка обслуживает несколько
организаций; пользователь видит только станки своих узлов иерархии, киоск — только свой станок или
участок, сотрудник сервиса — станки всех клиентов. Проба и драйвер FOCAS по-прежнему

## Упрощения и ограничения

- **Коллекторы одной площадки доверяют друг другу.** ACL разделяет площадки, `ingest` проверяет, что коллектор зарегистрирован на площадке топика, но `collector_id` в теле телеметрии не связан с учётной записью брокера: коллектор может подписать данные именем соседа по площадке. Heartbeat привязан к топику с собственным ID.
- **Учётные записи коллекторов** задаются в `.env` (`MM_MQTT_COLLECTORS`) и требуют перезапуска брокера; регистрация коллектора в админке — отдельное действие.
- **Учётные записи симуляторов** создаются в брокере всегда, если заданы `MM_MQTT_SIM_*_PASSWORD`; они могут писать только в площадки демо-организации.
- **Демо-пользователи с паролем `demo`** создаются при `MM_DEMO_DATA=true`, и так стоит в `.env.example`. В эксплуатации — `false`.
- **Журнала аварий в API нет.** Сервис видит аварии как состояние ALARM в таймлайне и на дашборде, наработку — в аналитике; коды аварий из `machine_events` наружу пока не отдаются.
- **Сессия — JWT без отзыва.** Отключённый пользователь теряет доступ сразу (пользователь проверяется в базе на каждый запрос), но сменённый пароль не завершает уже открытые сессии.
- **Киоск видит имя своей площадки** в `/admin/sites` — больше структуры ему не показывается.
- **Миграция `0004` необратима**; производные данные после неё пересчитываются из сырых (по суткам за шаг).
- **Интерфейс минимальный:** выбор узла в админке — списками, «дни недели» и «перерывы» смен — JSON, у мастера в меню есть «Админка» (справочники на чтение).
