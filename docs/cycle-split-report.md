# Отчёт: разделение цикла (feat/cycle-split)

Дата: 2026-11-24 · Ветка: `feat/cycle-split` · Решение: ADR 0008

## Итог

Каждый цикл станка — от детали до соседней детали — разложен на машинное время (RUN), смену заготовки
(от детали до следующего запуска) и прерывания (IDLE, STOP, ALARM, SETUP после запуска). Длинная пауза
между деталями считается простоем, а не сменой заготовки. Наладка (первая деталь после смены программы)
и циклы с потерей связи в статистику не входят. Циклы — производная таблица: `worker` строит её вместе
с таймлайном, и `make recalc` пересчитывает её вместе с ним. В аналитике — медианы, гистограммы и
сравнение с нормой по программам, сменам и дням; на экране оператора — последний цикл и норма.

## Что сделано

| Часть | Содержание |
|---|---|
| Правила | `app/timeline/cycles.py`: чистая функция `build_cycles` (части события → цикл) и деление промежутка порогом `pause_threshold` / `split` |
| Хранение | Миграция `0010`: таблица `cycles` (факты цикла: машинное время, промежуток до запуска, прерывания по видам, OFFLINE, вид цикла), `machines.cycle_pause_threshold_s`; отметки пересчёта от первой детали каждого станка — история перестраивается сама |
| Пересчёт | `timeline.rebuild` после `part_events` строит заново циклы, окно которых задевает пересчитанный период, и цикл через его правую границу |
| Порог | Настройка станка в админке («Порог простоя между деталями, мин»; пусто — авто: 3 × медиана обработки программы, не меньше 10 мин); применяется при чтении — менять можно без пересчёта |
| API | `GET /cycles/stats?from&to&site_id|area_id|machine_id[&program]` — по станку и программе: циклы всего / в статистике / наладка / неполные, медианы обработки, смены заготовки и цикла, доля прерываний, простои между деталями, норма на деталь и отношение к ней, гистограммы, по сменам и по дням. Маршрут — в тесте изоляции |
| Экран оператора | «Последний цикл / норма»: длительность от детали до детали и норма; ниже — время обработки и пометка «наладка» / «неполный» |
| Аналитика | Карточка «Циклы по программам» (24 часа / 7 дней / 30 дней): таблица, по клику — гистограммы обработки и смены заготовки, разбивка по сменам и дням |

## Критерии готовности: golden-тесты

`backend/tests/golden/test_cycle_golden.py` — от сырых выборок (раз в секунду, как коллектор) через правила
таймлайна и `part_events` к циклам:

| Сценарий | Что проверено |
|---|---|
| Обычная работа | 60 с обработки + 20 с смены заготовки: 4 цикла, у каждого обработка 60, промежуток 20, прерываний нет; цикл заканчивается деталью |
| Длинная пауза | промежуток 1800 с при пороге max(3 × 60 с, 10 мин) = 600 с — простой, а не смена заготовки; настройка станка (15 с) меняет деление |
| Прерывания внутри обработки | остановка подачи 40 с и авария 50 с после запуска — прерывания (IDLE, ALARM), не смена заготовки |
| Смена программы | первая деталь по новой программе — `setup`, следующие — `normal` |
| Обрыв связи внутри цикла | 90 с без данных во время обработки — `incomplete` (OFFLINE внутри), соседние циклы целые |
| Сброс счётчика | сброс между деталями не даёт лишнего цикла; цикл через сброс — обычный |
| Несколько деталей за цикл | счётчик растёт на 4 — один цикл на 4 детали |
| Начало данных | первая деталь цикла не образует, незаконченная деталь не сохраняется |

На реальной БД (`backend/tests/test_cycles_db.py`):

- циклы строятся вместе с таймлайном; опоздавшие данные из буфера (деталь в середине суток без данных)
  перестраивают их, и результат совпадает с пересчётом с нуля по суткам (`make recalc`);
- `GET /cycles/stats`: медианы 50 / 20 / 70 с, порог 600 с (авто), пауза 1820 с — простой, норма 45 с на
  деталь и отношение 1,111, гистограммы, разбивка по сменам и дням; порог станка 3600 с меняет деление сразу,
  без пересчёта; оператору аналитика закрыта (403);
- live-состояние для экрана оператора: последний цикл 70 с, обработка 50 с, норма 45 с.

## Решения, которые стоит подтвердить

- Порог по умолчанию считается по медиане машинного времени программы **за выбранный период** и применяется
  при чтении, а не хранится: так смена порога не требует пересчёта, а циклы не зависят друг от друга.
- «Последний цикл» на экране оператора — от детали до детали (вместе со сменой заготовки и прерываниями);
  время обработки показано ниже. Норма — норма цикла программы на деталь × число деталей.
