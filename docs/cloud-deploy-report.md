# Отчёт: развёртывание на облачной VM (feat/cloud-deploy)

Дата: 2026-11-25 · Ветка: `feat/cloud-deploy` · Решение: ADR 0010 · Runbook: `docs/runbooks/cloud-install.md`

## Итог

Сервер ставится на облачную VM тремя командами: `make env-prod` (случайные пароли), заполнить ключи S3, `make prod-up`.
Caddy получает сертификат Let's Encrypt для домена и обслуживает HTTPS. Mosquitto принимает коллекторы по TLS на 8883
с тем же сертификатом и сам подхватывает продлённый. Наружу открыты только 80, 443 и 8883. Со значениями из
`.env.example` сервер в prod не стартует и называет переменные, которые нужно поменять. Вход ограничен пятью неудачными
попытками в минуту на пару адрес + логин. Каждую ночь база уходит в S3; восстановление на чистый том проверено на стенде
и возвращает ровно те же данные.

## Что сделано

| Часть | Содержание |
|---|---|
| Prod-стек | `deploy/docker-compose.prod.yml` поверх основного: Caddy (80, 443), Mosquitto (8883), `backup`; без симуляторов; `MM_ENV=prod`, `MM_DEMO_DATA=false`, `MM_PUBLIC_URL=https://MM_DOMAIN`; у web снят порт (`!reset`) |
| HTTPS | `deploy/caddy/Caddyfile`: Let's Encrypt для `MM_DOMAIN`, 80 → 443, HTTP/3 выключен; `/api/*`, `/ws/*` — прямо в API с `X-Real-IP {remote_host}`, остальное — в web. `MM_TLS_ISSUER=internal` — свой CA Caddy для стенда |
| MQTT по TLS | entrypoint Mosquitto: ждёт сертификат домена в томе Caddy, копирует его себе, слушает 8883 (TLS 1.2+); раз в час сверяет с файлом Caddy и при продлении шлёт SIGHUP |
| Коллектор | `tls: true` и порт 8883 по умолчанию, проверка сертификата и имени по системным корневым; `ca_file` — свой CA; симуляторы `make up` — `tls: false` |
| Отказ старта | `MM_ENV=prod`: api (`python -m app.api`), ingest, worker и migrate выходят с кодом 2 и списком переменных (секрет `change-me…` или короче 32, пароль суперадмина `admin`/пустой, пароли БД и брокера `change-me…`, `MM_DEMO_DATA=true`); Mosquitto — то же для паролей брокера. `make env-prod domain=… email=…` — `.env` со случайными паролями, существующий не перезаписывается |
| Вход | Redis: больше 5 неудач за 60 с по паре адрес + логин — 429 с `Retry-After`, успех сбрасывает счёт; без Redis — ограничение выключено, вход работает. На форме входа — «Слишком много неудачных попыток…» |
| Заголовки, киоск | `nosniff`, `DENY`, `no-referrer` — у всех ответов API (middleware) и nginx (без удвоения в `/api/`); токен киоска из `?token=` убирается из адресной строки, остальное в адресе остаётся |
| Бэкапы | `deploy/backup/` — образ TimescaleDB 2.32.0-pg16 + rclone 1.76.0 (из официального образа), `mm-backup`: ночной `pg_dump -Fc` → S3 в `MM_BACKUP_TIME` (UTC), проверка дампа, удаление копий старше 30 дней только после успешной загрузки; `restore NAME --yes`; `restore-check` во временную базу `restore-check-db` со сравнением. Команды `make backup-now`, `backup-list`, `restore-check`, `restore file=… confirm=yes` |
| Демо-организация | `make prod-drop-demo` (`deploy/scripts/drop-demo.sql`): одна транзакция, отказ при данных коллекторов |
| CI | job `deploy`: shellcheck скриптов, `docker compose config` dev и prod (с `.env` от `env-prod`), `caddy validate`; образ `backup` — в сборке образов |
| Документы | ADR 0010, `docs/runbooks/cloud-install.md` (VM, 152-ФЗ, DNS, установка, обновление, восстановление, коллектор клиента, чек-лист), ARCHITECTURE (п. 3.7, 5.1, 7.1, 8.1, 8.3, 9, 10), `collector-network.md` (8883 и TLS-инспекция), CLAUDE.md (команды, CI) |

## Найдено по ходу

| Что | Как нашлось | Что сделано |
|---|---|---|
| «Демо-предприятие» создают миграции, а не `MM_DEMO_DATA`: в prod оно было бы у всех на виду | разбор миграций | `make prod-drop-demo`, пункт чек-листа; автоматически не удаляется (ADR 0010) |
| Через nginx заголовки безопасности ответов API удваивались бы (дважды `X-Frame-Options` браузер может проигнорировать) | разбор конфигурации | `proxy_hide_header` в `/api/` |
| В песочнице закрыто зеркало Alpine: `apk add rclone` невозможен | сборка образа | rclone берётся из официального образа multi-stage сборкой — при сборке ничего не скачивается, так даже надёжнее |
| В `restore-check` коллекторы всегда «отличались»: heartbeat меняется каждые 15 с | стенд | для `collectors` сравниваются только id, площадка и имя |
| У TimescaleDB `pg_dump` печатает подсказки про циклические внешние ключи | стенд | ожидаемо, восстановление проходит с `--exit-on-error` |

## Решения, которые стоит подтвердить

- **Без Redis вход не ограничивается** (предупреждение в логе): отказ кэша не закрывает вход всем.
- **Блокируется пара адрес + логин.** За общим NAT клиента пять ошибок одного логина закрывают этот логин на минуту
  для всех за этим адресом; чужой адрес закрыть вход владельцу не может.
- **В бэкап идёт только база.** Сертификаты Caddy получит заново, данные брокера — очередь сообщений; `.env` хранит
  владелец (менеджер паролей): без него сбрасываются только сессии.
- **Шифрования бэкапов на стороне сервера нет** — закрытый бакет и ключ только к нему; при требовании клиента —
  шифрование хранилища провайдера или rclone crypt.
- **`MM_BACKUP_TIME` — в UTC** (по умолчанию 23:30 UTC = 02:30 по Москве).
- **Журнал доступа nginx** в контейнере web содержит адрес первой загрузки ссылки киоска (с токеном); выключать
  журнал или вырезать параметры — отдельным решением.
- **Мониторинг** (Prometheus, Grafana) не делался; о проблемах с бэкапом сейчас говорит только лог `backup` — повод
  для уведомлений задачи 2.
