# ADR 0007. Осторожный опрос стойки: минимальный набор сигналов по умолчанию

- Статус: принято
- Дата: 2026-11-24

## Контекст

Первая реальная стойка (Fanuc 0i-MD) ещё не подключена. Как она переносит опрос по FOCAS2 — не измерено:
каждый вызов занимает встроенный Ethernet и процессор стойки, а число одновременных подключений ограничено.
До сих пор коллектор раз в секунду читал всё: статус, программу, подачу, обороты, нагрузку шпинделя,
счётчик деталей. Проба делала то же.

## Решение

1. **Только чтение.** Ни проба, ни коллектор не вызывают функций записи в ЧПУ (`cnc_wr*`, `pmc_wr*`,
   загрузка и удаление программ). Тест проверяет исходники edge на такие имена.
2. **Минимум по умолчанию.** Коллектор читает набор сигналов из конфига станка (`signals`); по умолчанию —
   `status` (`cnc_statinfo`), `program` (`cnc_rdprgnum`, `cnc_exeprgname`), `part_count` (макро #3901 или
   параметр 6711), `alarms` (`cnc_rdalmmsg2`, только пока статус показывает аварию). Этого хватает
   таймлайну и OEE. `feed_actual`, `spindle_speed`, `spindle_load` читаются только если перечислены явно;
   не включённый сигнал не стоит ни одного вызова и не публикуется. `status` обязателен.
3. **Период опроса** — 1 с по умолчанию, допускается 2–5 с (`poll_interval_ms` 1000–5000 для FOCAS).
4. **Проба** в обычном режиме и в `--watch` читает тот же минимум (плюс `cnc_sysinfo` один раз и оба
   источника счётчика деталей), с временем ответа каждого вызова.
5. **Разведка `--recon`** — один проход без повторов (с `--watch` несовместима): коррекции через
   `pmc_rdpmcrng` G0012 (подача, инверсная логика `*FV`: 255 − значение), G0030 (шпиндель), G0014
   (ускоренный ход, ROV1/ROV2), инструмент #4120, `cnc_rdtimer`, `cnc_rdsvmeter` с именами осей
   (`cnc_rdaxisname`), `cnc_rddynamic2` одним вызовом, подача, обороты, нагрузка шпинделя; по запросу —
   диапазоны PMC (`--pmc`) и номера диагностики (`--diag`). Каждый сигнал читается независимо:
   ошибка одного не мешает остальным, `EW_FUNC`/`EW_NOOPT` — «не поддерживается стойкой».
6. Расширять набор коллектора — только после разведки и замеров времени ответа на этой стойке.

## Последствия

- На стенде симулятора подача, обороты и нагрузка включены явно в `config.sim.*.yaml`, чтобы графики
  демо не опустели; у реальной стойки по умолчанию их нет — график телеметрии в журнале аварий будет пустым,
  пока сигналы не включат.
- Раскладка структур для `pmc_rdpmcrng`, `cnc_rdtimer`, `cnc_rdsvmeter`, `cnc_rdaxisname`, `cnc_rddynamic2`,
  `cnc_diagnoss` взята по fwlib32.h для семейства 0i-D / 30i и проверена только на поддельной библиотеке;
  длина буфера `cnc_rddynamic2` для всех осей берётся из `max_axis` из `cnc_sysinfo` (иначе 32).
  Первый запуск `--recon` на стойке это подтвердит или опровергнет.
- Постоянное чтение нагрузок и коррекций в коллекторе, «чёрный ящик» PMC и автоопределение столкновений —
  не делаются, пока нет замеров.
