# ADR 0010. Развёртывание на облачной VM: HTTPS, MQTT по TLS, защита по умолчанию, бэкапы

- Статус: принято
- Дата: 2026-11-25

## Контекст

Перед первым внешним клиентом сервер переезжает с машины разработчика на облачную VM в интернете. Нужен
необходимый минимум: HTTPS по доменному имени, MQTT по TLS для коллекторов клиента, наружу — только нужные
порты, отказ старта со значениями паролей по умолчанию, ограничение попыток входа, заголовки безопасности,
ночные бэкапы с проверенным восстановлением. Row-level security и журналы аудита не делаются.

## Решение

1. **Prod — отдельный compose-файл** `deploy/docker-compose.prod.yml` поверх основного (`make prod-up`). Без профиля
   `dev`: симуляторов нет; `MM_ENV=prod`, `MM_DEMO_DATA=false`, `MM_PUBLIC_URL=https://MM_DOMAIN`. Наружу
   публикуются только Caddy (80, 443) и Mosquitto (8883). БД, Redis, API, контейнер web и 1883 — только внутри сети
   compose (у web порт снят через `!reset`, нужна Docker Compose 2.24+).
2. **Caddy** — reverse proxy с автоматическим HTTPS: сертификат Let's Encrypt для `MM_DOMAIN` (HTTP-проверка через
   порт 80), продление — сам Caddy. `/api/*` и `/ws/*` идут прямо в API, остальное — в web (статика). HTTP/3
   выключен (только TCP 443). `MM_TLS_ISSUER=internal` — сертификат из собственного CA Caddy, только для стенда без
   публичного домена.
3. **Сертификат для MQTT — тот же, что у Caddy.** Mosquitto монтирует том данных Caddy только на чтение, при старте
   ждёт сертификат домена (`certificates/<issuer>/<domain>/<domain>.crt|.key`), копирует его себе (файлы Caddy
   читает только root) и слушает 8883 с TLS 1.2+. Раз в `MM_MQTT_CERT_CHECK_S` (час) сравнивает копию с файлом
   Caddy; если Caddy продлил сертификат — копирует и шлёт брокеру SIGHUP: Mosquitto 2 перечитывает сертификаты
   слушателей без перезапуска (проверено). Отдельного ACME-клиента и второго процесса продления нет; 1883 остаётся
   для `ingest` внутри сети.
4. **Коллектор:** `tls: true` по умолчанию, порт 8883; сертификат сервера проверяется по системным корневым
   (на Windows — хранилище системы), имя проверяется всегда. `ca_file` заменяет корневые своим CA (самоподписанный
   стенд, корпоративный CA). Симуляторы `make up` — явно `tls: false` внутри сети compose.
5. **Отказ старта со значениями по умолчанию.** При `MM_ENV=prod` api, ingest, worker и migrate не стартуют (код 2,
   сообщение с именами переменных и командой `make env-prod`, без трассировки), если: `MM_SECRET_KEY` начинается с
   `change-me` или короче 32 символов; `MM_ADMIN_PASSWORD` пустой или `admin`; пароль БД или `MM_MQTT_BACKEND_PASSWORD`
   пустой или из `.env.example` (`change-me…`); `MM_DEMO_DATA=true` (у демо-учётных записей известный пароль).
   Mosquitto в prod так же отказывается от паролей `change-me…` у backend и у коллекторов. API запускается
   `python -m app.api`: настройки проверяются до uvicorn. `make env-prod domain=… email=…` создаёт `.env` со
   случайными паролями (буквы и цифры: значения входят в URL БД и файл паролей брокера) и не перезаписывает
   существующий.
6. **Ограничение попыток входа** — в Redis, фиксированное окно: больше `login_max_failures` (5) неудачных входов за
   `login_failure_window_s` (60 с) по паре адрес + логин — 429 с `Retry-After`, даже с верным паролем; успешный вход
   сбрасывает счёт. Блокируется пара, а не логин: чужой адрес не может закрыть вход владельцу. Логин в ключе — хеш.
   Адрес — `X-Real-IP`, который ставит прокси перед API (Caddy — `{remote_host}`, не доверяя `X-Forwarded-*`
   клиента; nginx — `$remote_addr`); API наружу не публикуется, поэтому клиент заголовок не выбирает. Без Redis
   ограничение выключается с предупреждением в логе: отказ кэша не должен закрыть вход всем.
7. **Заголовки** `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer` — у всех
   ответов API (ASGI-middleware) и nginx (статика; копии из API в `/api/` скрываются, чтобы заголовок не удваивался).
   Токен киоска после чтения из `?token=` сохраняется в `localStorage` и убирается из адресной строки
   (`history.replaceState`), остальные параметры и якорь остаются.
8. **Бэкапы.** Сервис `backup` (образ TimescaleDB той же версии + статический rclone из официального образа) каждую
   ночь в `MM_BACKUP_TIME` (UTC) делает `pg_dump -Fc`, проверяет его `pg_restore --list` и загружает в S3-совместимое
   хранилище (`MM_BACKUP_S3_*`, бакет создаётся заранее). После успешной загрузки удаляются копии старше
   `MM_BACKUP_KEEP_DAYS` (30) — свежая копия остаётся всегда. Восстановление (`make restore`) пересоздаёт базу и
   оборачивает `pg_restore --exit-on-error` в `timescaledb_pre_restore()` / `timescaledb_post_restore()`.
   `make restore-check` восстанавливает копию во временную чистую базу и сравнивает справочники целиком, сырые и
   производные данные — по числу строк.
9. **Демо-организация** создаётся миграциями (`0002`, `0004`), а не `MM_DEMO_DATA`. Удаляется явной командой
   `make prod-drop-demo` (одна транзакция; отказ, если у её станков есть данные коллекторов), не автоматически.

## Последствия

- Для HTTPS и MQTT по TLS нужны DNS-запись домена на IP сервера и открытые 80/443 до первого старта: пока Caddy не
  получил сертификат, Mosquitto ждёт его и коллекторы не подключаются.
- Сессии пользователей подписаны `MM_SECRET_KEY`: при восстановлении на новом сервере с новым `.env` все входят
  заново; ссылки киосков (хеш SHA-256 без секрета) продолжают работать. `.env` нужно хранить отдельно от сервера.
- Ограничение входа по адресу: за общим NAT клиента пять ошибок одного логина блокируют этот логин для всех за
  этим адресом на минуту.
- Шифрования бэкапов на стороне сервера нет: бакет должен быть закрытым, ключи — с правами только на него.
- Журнал доступа nginx в контейнере web содержит адрес первой загрузки страницы киоска (с токеном).
