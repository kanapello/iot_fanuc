# ADR 0012. Главный экран-сводка предприятия

- Статус: принято
- Дата: 2026-11-25

## Контекст

Владелец после просмотра интерфейса: верхнее меню и стартовая страница по роли неудобны. Нужен главный экран
как сводка предприятия в системах класса MachineMetrics, своим стилем: загрузка, OEE, производительность,
доступность с изменением к прошлому периоду и обычным уровнем; выпуск; станки сейчас; простои по причинам;
станки с загрузкой ниже обычной; программы медленнее нормы; боковая панель станка. Для демо нужна история
длиннее 8 часов.

## Решение

1. **Каркас интерфейса.** Меню слева (сворачивается до иконок, ниже 768 px — за кнопкой), профиль и выход —
   внизу меню, площадка и участок — вверху экрана; страницы каркаса работают на этом выборе. Пункты — по
   флагам `me.menu`, «Обзор» — при `menu.analytics`. `/` — обзор для ролей с аналитикой; киоски и остальные
   роли переадресуются как раньше. «Станки» (`/machines`) — плитки ТВ-дашборда тем же компонентом;
   `/dashboard`, `/dashboard/:areaId`, `/operator/:id`, `/m/<код>` — без меню.
2. **Один маршрут** `GET /api/v1/overview?period=shift|today|yesterday|7d|30d&site_id=&area_id=`, область
   доступа — `AnalyticsMachines`. Сводка — по одной площадке: сутки и смены — в её часовом поясе.
3. **Загрузка ≠ доступность.** Загрузка = время RUN / календарное время периода по `state_intervals`, включая
   часы вне смен и перерывы. OEE, производительность и доступность — из сумм компонентов `oee_hourly` формулой
   `oee.calc.ratios` (не среднее часовых процентов); час без смены — пропуск на графике. Формулы OEE не менялись.
4. **Сравнения.** Шаг — час (смена, сегодня, вчера) или день (7, 30 дней). Прошлый период — такой же период
   перед текущим (для смены — прошлый экземпляр той же смены), сравнивается та же прошедшая часть. Обычный
   уровень шага — тот же шаг на 4 таких же днях недели назад, по суммам. Отрезок раньше начала истории станков —
   «нет данных» (`null`): прошлый период сравнивается, только если весь лежит в истории, обычный уровень — по
   имеющимся неделям. Пороги «ниже обычной» (10 п.п.) и «медленнее нормы» (10 %, медиана машинного времени на
   деталь против нормы на деталь) — `MM_OVERVIEW_UTILIZATION_DROP_PP`, `MM_OVERVIEW_SLOW_CYCLE_PCT`.
5. **Без тяжёлых запросов.** Все отрезки периода собираются в один список, и каждый источник читается одним
   запросом по нему (`timeline.state_seconds`, `timeline.part_totals`, `oee.component_sums`); простои —
   `reports.downtime_pareto`; циклы — `cycles.summaries` (общая часть `cycles.stats` без гистограмм). Сырую
   телеметрию сводка не читает.
6. **Демо-история.** Прежний механизм симулятора: `backfill_hours` до 672 (28 дней — меньше срока сжатия
   телеметрии 30 дней), последние `backfill_detail_hours` (72) — с шагом 5 с, старше — не мельче 30 с. В демо-стенде — 21 день истории (замер `make up`
   с нуля: 8,7 мин). Параметр станка `recent_profile` / `recent_hours`: с момента «N часов до первого запуска» станок идёт по другому
   сценарию (момент хранится рядом с буфером, счётчик деталей продолжается). По умолчанию выключен.

## Последствия

- Живой блок обновляется по `/ws/live`, остальное — раз в минуту.
- Шаг 30 с огрубляет циклы короче минуты: в старой части демо-истории медианы машинного времени искажены
  (до +58 % / −29 % к норме), поэтому на демо «медленнее нормы» за 7 и 30 дней показывает и ложные программы.
  Загрузка и OEE от шага не зависят. На реальных данных этого нет.
- «Открыть станок» ведёт на `/m/<код>`: страница сама выбирает экран по роли (ADR 0009). Код паспорта отдаётся
  только в сводке, ролям с аналитикой.
