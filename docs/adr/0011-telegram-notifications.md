# ADR 0011. Уведомления в Telegram

- Статус: принято
- Дата: 2026-11-25

## Контекст

Мастер, администратор клиента и сервис узнают о событиях с опозданием — когда откроют экран. Нужны уведомления
в Telegram: авария, предупреждения стойки, коллектор без связи, простой без причины, заявки на ремонт, ТО по
наработке. Сервер может стоять без публичного адреса (у клиента в цеху), поэтому вебхук Telegram не подходит.
Почта, вебхуки и SMS сейчас не делаются.

## Решение

1. **Модуль `app/notify`** (запланирован в CLAUDE.md). Работает внутри `worker`: проверка условий — на такте
   после таймлайна, отправка очереди и бот — отдельными задачами того же процесса. Данные других модулей — только
   через их сервисные функции (`timeline.latest_sample` / `current_state`, `journal.current_reason`,
   `alarms.episodes`, `requests.history_since`, `maintenance.schedule`, `admin.list_collectors_system`,
   `admin.area_stop_alert_minutes`).
2. **Бот — long polling** (`getUpdates`), без публичного адреса. Токен и имя бота — `MM_TELEGRAM_BOT_TOKEN`,
   `MM_TELEGRAM_BOT_USERNAME` в `.env`; без токена уведомления выключены. Токен не попадает в логи (журнал httpx
   выключен, текст ошибок очищается). Один процесс `worker` на установку — второй получил бы 409 от Telegram.
3. **Привязка.** В профиле «Подключить Telegram» выдаёт одноразовую ссылку `t.me/<бот>?start=<код>` на 15 минут
   (в базе — только хеш кода; новая ссылка отменяет прежнюю). `/start <код>` в личном чате с ботом привязывает
   чат: один пользователь — один чат, и чат принадлежит одному пользователю. Групповые чаты не принимаются.
   Отвязать — в профиле или `/stop` в чате. Бот, заблокированный пользователем (403), отвязывается сам.
4. **События и получатели по умолчанию** — роль, выданная на узле предмета события, и тот же объём доступа, что
   в API (`identity.user_scope` — общее построение области доступа для запросов и уведомлений):

   | Событие | Когда | Кому |
   |---|---|---|
   | `alarm` | `alarm_code` 1 в свежей телеметрии (`statinfo.alarm`) | мастер участка, сервис |
   | `warning` | `alarm_code` 2 (батарея) или 3 (вентилятор) | сервис |
   | `collector_offline` | нет heartbeat дольше 5 мин | сервис, администратор организации |
   | `buffer_lost` | коллектор запустился с пустым буфером | сервис, администратор организации |
   | `stop_no_reason` | STOP без причины дольше `areas.stop_alert_minutes` (по умолчанию 10) | мастер участка |
   | `repair_new` | новая заявка | сервис |
   | `repair_status` | принята, в работе, выполнена, аннулирована | администратор, мастер |
   | `maintenance_due` | регламент перешёл в «скоро» или «пора» | сервис |

   Пользователь выключает типы у себя в профиле (по умолчанию включены все типы его ролей). Суперадмин без ролей
   уведомлений не получает.
5. **Антиспам и «восстановлено».** Для каждого события и предмета (`machine:12`, `collector:edge-1`, `request:7`,
   `plan:5`) хранится состояние условия. Начало объявляется, если то же событие этого предмета не объявлялось
   `MM_NOTIFY_REPEAT_MINUTES` (15) минут; конец объявленного эпизода — коротким «восстановлено» (авария и
   предупреждение сняты, коллектор снова на связи, простой без причины закончился). Необъявленное начало — без
   «восстановлено». Телеметрия старше 10 минут ни начинает, ни заканчивает аварию: поздние данные из буфера — не
   новость; коллектор без связи больше суток считается выведенным; потерянный буфер — новость в течение часа.
6. **Очередь — таблица `notification_outbox` в PostgreSQL.** Сообщение на пользователя; отправка берёт строки
   `FOR UPDATE SKIP LOCKED`, чат определяется в момент отправки (отвязанный не получает). Ошибка — повтор через
   10 с, 30 с, 1, 5, 15, 30 мин (или через `retry_after` от Telegram), после 8 попыток — отказ с ошибкой в строке.
   Ошибки Telegram и сбои проверки условий пишутся в лог и не останавливают `worker`.
7. **Тексты** — на русском, со ссылками на `MM_PUBLIC_URL`: авария — журнал аварий с раскрытым эпизодом
   (`/alarms?machine=…&at=…`), простой — экран оператора (там мастер укажет причину), заявка — `/repairs?request=…`.
8. **Уведомления — побочный эффект, не производные данные** (правило 2 их не касается): пересчёт таймлайна ничего
   не отправляет повторно. Первый старт не рассылает старую историю заявок.

## Последствия

- Без интернета у сервера (или без доступа к `api.telegram.org`) сообщения копятся в очереди и уходят после
  восстановления связи — до 8 попыток.
- Предупреждение `warning` объединяет батарею и вентилятор; смена одного на другое без снятия — тот же эпизод.
- Получатели определяются в момент события: роль, выданная позже, прошлых сообщений не получит.
- Права в уже идущем long polling и в отправке перепроверяются на каждом событии; отзыв токенов при смене пароля и
  перепроверка прав в WebSocket — вне этой задачи.
