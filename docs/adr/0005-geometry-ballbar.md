# ADR 0005. Геометрическая точность: модель данных ballbar и права сервиса

- Статус: принято, требует подтверждения владельцем проекта
- Дата: 2026-11-17

## Контекст

Мониторинг идёт в комплексе с контролем геометрической точности станков: сервисная компания проводит
тесты Renishaw QC20 (Ballbar 20) у клиентов. Нужно хранить тесты в карточке станка, оригиналы `.b5r` и
PDF-отчётов, результаты с единицами, допуски, тренды и срок следующей проверки. Формат `.b5r` не открыт,
автоматический разбор появится позже, по образцам.

## Решение

1. **Тест и результаты раздельно.** `ballbar_tests` — настройка теста; `ballbar_results` — строки
   «параметр + ось + направление + значение + единица». Набор параметров, их единицы и допустимые
   оси/направления заданы каталогом в коде (`app/geometry/catalog.py`); ось берётся из плоскости теста.
   Единица копируется в строку результата, чтобы история не зависела от будущих правок каталога.
2. **Сырые точки круга** — отдельная таблица `ballbar_traces` (массивы `real[]` углов и отклонений на
   направление прохода). Сейчас её заполняет API импорта и демо-данные, позже — разбор `.b5r`.
3. **Оригиналы в PostgreSQL** (`ballbar_files`, `bytea`, до 25 МБ на файл), а не на диске: одна база,
   один бэкап (принцип «Одна БД»). Триггер запрещает UPDATE и DELETE — файлы хранятся всегда; ошибочный тест
   аннулируется, а не удаляется.
4. **Допуски** на станок или на модель станка (новое поле `machines.model`), с необязательными
   плоскостью и осью. Выбирается самая узкая строка: станок важнее модели, затем плоскость, затем ось.
   Превышение — по модулю значения (ошибки ballbar знаковые). Статус вычисляется при чтении, поэтому
   изменение допуска сразу меняет подсветку без пересчёта.
5. **Допуски моделей общие для всех организаций** и ведутся сервисом (роль `service`) или суперадмином:
   модель станка — не данные клиента, стандарт модели один. Допуски конкретного станка ведут его
   организация (технолог, администратор) и сервис.
6. **Права.** Новые права `geometry.view` (мастер, технолог, администратор, сервис) и `geometry.edit`
   (технолог, администратор, сервис). **Роль `service` впервые получает запись** — тесты, файлы, допуски,
   правила проверки, отметки «столкновение» — по станкам всех организаций. Это расширяет ADR 0004, где
   сервис только читал.
7. **Следующая проверка** — чистая функция от политики станка, даты последнего теста, наработки (RUN из
   таймлайна), аварий из `machine_events` и отметок «столкновение» после теста. Модули читают чужие
   данные только через сервисные функции владельцев (`timeline.run_seconds_since`, `ingest.health.alarms_since`,
   `admin.journal.list_collisions`).
8. **Тренд** строится только по тестам с одинаковыми плоскостью, радиусом и подачей; дуга в ключ не входит.

## Последствия

- Изоляция: все новые маршруты проходят тот же тест изоляции, что и остальные (49 закрытых маршрутов).
- Разбор `.b5r` пишется по образцам в `backend/tests/fixtures/ballbar/` (README там же); golden-тест уже
  есть и пропускается, пока образцов нет.
- Допуск не зависит от радиуса и подачи теста; если понадобится — добавить их в ключ допуска.
- Файлы в базе увеличивают её объём и бэкапы: оценка — сотни КБ на тест.
