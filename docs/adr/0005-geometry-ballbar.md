# ADR 0005. Геометрическая точность — внутренний архив сервиса с трендом

- Статус: принято (пересмотрено 2026-11-22)
- Дата: 2026-11-17, пересмотр 2026-11-22

## Контекст

Сервисная компания проводит у клиентов тесты Renishaw QC20 (Ballbar 20). Первая версия модуля
(2026-11-17) анализировала результаты: допуски на станок и модель, подсветка превышений, расчёт
следующей проверки по сроку, наработке и авариям, рабочий список сервиса, заготовка разбора `.b5r`.
Права на геометрию были у клиентов (мастер, технолог, администратор).

Владелец проекта решил упростить: геометрия — внутренний архив сервиса, клиенты его не видят, а анализ
откладывается до появления реальных данных и требований к нему.

## Решение

1. **Только сервис.** Права `geometry.view` и `geometry.edit` есть только у роли `service` (и у
   суперадмина). У мастера, технолога и администратора клиента их нет: пункт «Сервис» в меню скрыт,
   все маршруты архива отвечают **404** — даже по станкам собственной организации, как будто архива нет.
2. **Отметка «столкновение» — ввод события с участка.** Её ставят оператор и мастер (право ввода
   оператора), а также сервис; просматривают отметки только сервис и суперадмин.
3. **Что хранится.** Тесты в карточке станка (настройка, ручной ввод результатов по каталогу параметров
   с единицами), оригиналы `.b5r` и PDF в PostgreSQL — неизменяемые (триггер запрещает UPDATE и DELETE),
   сырые точки круга для полярного графика (API импорта), журнал выполненных ремонтов.
4. **Тренд параметра.** Сравниваются тесты одного шаблона (без учёта регистра и пробелов); тесты без
   шаблона — с одинаковыми плоскостью, радиусом, подачей и дугой. На графике отмечаются события:
   отметки «столкновение» и выполненные ремонты.
5. **Без анализа.** Нет допусков, подсветки превышений, статусов, расчёта следующей проверки и
   внеплановых проверок по авариям. В карточке станка — только дата последнего теста и сколько дней
   прошло. Экран «Сервис» — список станков с датой последнего теста, без статусов.
6. **Разбор `.b5r` отложен** вместе с анализом; заготовка парсера и его golden-тест удалены.
7. Миграция `0006` удаляет таблицы допусков и политик, индекс аварий, поле `machines.model` и признак
   источника результатов; добавляет таблицу `repair_records`.

## Последствия

- Клиент не узнаёт из системы о результатах тестов геометрии; отчёты ему передаются вне системы.
- Тест изоляции проверяет оба направления: чужая организация не видит архив, а пользователи клиента
  получают 404 на всех 16 маршрутах архива по своим станкам.
- Журнал ремонтов минимальный (дата, описание, инженер), без исправления и удаления — его заменит или
  расширит сервисный модуль заявок на ремонт.
- Возврат к анализу (допуски, сроки проверок) — новым решением, когда появятся реальные тесты и требования.
